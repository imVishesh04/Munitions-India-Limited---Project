# Public release checklist

- [ ] Confirm the internship agreement and project owner permit public source-code release.
- [ ] Confirm supervisor/organization approval in writing before publishing.
- [ ] Use only invented account names, password hashes, and sample PDFs.
- [ ] Keep `uploads/` empty in Git; never commit files users uploaded while testing.
- [ ] Do not restore original organization logos, SQL dumps, internal documents, or contact details without written approval.
- [ ] Inspect `git status` and the GitHub diff before every public push.
- [ ] Do not treat this demo as production-ready without a security review.
